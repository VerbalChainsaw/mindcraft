# Frozen capability contract

This is the durable verification-selection rule for Minecraft gameplay work.

A capability that has passed real physical acceptance stays closed. A later
higher-level change may traverse it when necessary, but traversal is not
recertification.

Reopen a frozen capability only when at least one of these is true:

1. source in the capability's owning contract changed;
2. a dependency, protocol, or contract it relies on changed; or
3. new physical runtime evidence directly contradicts the saved acceptance.

Prompt-form, noun, quantity, caller, scenario, preparation, repetition,
confidence-building, or a new higher-level mission are not reopening evidence.

When a higher-level proof traverses frozen mechanics, score only the changed
higher-level contract. If a lower-layer mechanic produces a materially new
failure class, preserve the evidence and reopen only that affected contract.

The gameplay certification map is a scenario library. Select scenarios from the
changed contract outward; never run the whole map by default.
