# Landmark-relative construction-site decision

## Trigger and calibration

Triviality gate: `trivial: no · continue`. Session 17 proved the stair
fixtures, their interaction stances, Pathfinder execution, and Paper state,
but the accepted Builder order was anchored about twenty-eight blocks from the
explicitly named picnic pad. The correction crosses natural intent, durable
Agenda normalization, and Builder site selection; several mechanisms are
credible and choosing the wrong owner would preserve a player-visible false
success.

Calibration was read directly because this runtime does not expose Codeplan's
named delegation tool and repository governance does not authorize spawning a
review workstream. Repository hard rules require exact target identity,
bounded immutable receipts, one durable Agenda/JobDirector path, project-owned
site judgment, package-owned locomotion, no new dependency, and real-Paper
verification. Existing code already has durable named-place memory, one latest
remembered structure order, normalized construction intent, and one
`bindSafeConstructionOrder` selector seam. Focused checks use `node:test` and
strict assertions around pure parsing/normalization and selector arguments.

Quality axes: repository style, hybrid-contract integrity, live-repair
methodology, runtime-compatible typed normalization, truthful unresolved-target
errors, focused testability, and blast radius/reversibility.

## Variants and hard gates

- **V1 — prompt-local zero-dep:** tell the model where the landmark is in the
  construction prompt. `G: fail` — `!designStructure` carries only local design
  coordinates and the action still binds beside the bot, so this cannot change
  the physical site.
- **V2 — inline-origin internal-reuse:** use the requester's current position
  as the selector origin whenever the request names a nearby object. `G: fail`
  — it replaces an explicit landmark with a different target and fails as soon
  as the requester walks away.
- **V3 — typed-contract internal-reuse:** resolve an explicit construction
  relation against durable player-named places, existing remembered-farm
  state, or the physically revalidated latest remembered structure, persist
  the bounded position/dimension/source in
  `constructionIntent`, and have the existing safe-site binder search around
  that origin. An explicit but unresolved reference fails before construction
  rather than falling back to the bot. `G: pass`.
- **V4 — external-store internal-reuse:** migrate home state to a multi-
  structure semantic registry with aliases, bounds, relation types, and a new
  resolver. `G: pass`; it can eventually support older structures and richer
  relations, but requires a persistence migration and a broader ownership
  surface than the observed immediate follow-up defect.
- **V5 — command-surface local-only:** add absolute target coordinates to
  `!designStructure` and let the model choose them. `G: fail` — the LLM is not
  allowed to invent world coordinates, and this bypasses grounded target
  selection.

Divergence: V1 changes only prompt data; V2 changes local origin choice; V3
adds a normalized persisted contract consumed by an existing binder; V4 adds
external durable state and a new resolver; V5 changes the public command
surface and relocates coordinate authority into the model.
