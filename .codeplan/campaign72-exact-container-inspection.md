container binding, structured interaction-stance receipts, package-owned

only after success, and no new store, controller, dependency, or parallel

missing seam is a typed observation entry plus a bounded manifest/report.

- V1 `inline-relay`: add `view_chest`, run existing nearest `!viewChest`, and
  relay ActionManager's text output. Diverges by local-only state and inline
  error/text path. `G: fail` — it does not bind the selected bedside container,
  carries no normalized manifest, and treats prose as the observation contract.
- V2 `typed-receipt`: add typed `inspect_container` with the existing exact
  container constraint, a thin `!viewChestAt` adapter over existing package
  mechanics, a bounded sorted manifest in skill evidence, and a grounded Agenda
  completion report; compile visit → inspect → return/Hold as ordinary dependent
  entries. Diverges by durable typed state, internal helper reuse, and structured
  return evidence. `G: pass`.
- V3 `composite-orchestrator`: add one durable `family_inspection` entry whose
  command internally visits Kid, opens/reports the chest, returns to Dad, and
  holds. Diverges by composite control flow and one action-level state machine.
  `G: pass`, but it duplicates Agenda sequencing/recovery and gives one action
  several existing owners.

Pairwise divergence: V1 vs V2 differs in state location and error carrier; V1
vs V3 differs in control flow and module boundary; V2 vs V3 differs in ordinary
Agenda sequencing versus a composite action state machine.
